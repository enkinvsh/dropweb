# Заголовки подписки dropweb

dropweb-app читает HTTP-заголовки ответа подписки и применяет их к интерфейсу и настройкам клиента — концепция «клиент-губка». Заголовки отправляются панелью (Remnawave) вместе с содержимым подписки. Все кастомные заголовки начинаются с `dropweb-`.

Документ описывает **темизацию**. Прочие `dropweb-*` заголовки (`servicename`, `servicelogo`, `widgets`, `view`, `globalmode`, `settings`, `cabinet`, `account`) существуют, но здесь не специфицируются.

---

## 1. dropweb-custom — гейт применения

Управляет тем, **когда** применять все `dropweb-*` настройки:

| Значение | Поведение |
|---|---|
| `add` | Применить только при первом добавлении профиля |
| `update` | Применять при каждом обновлении подписки и при переключении профиля |
| (нет заголовка / иное) | Не применять `dropweb-*` вообще |

> Без `dropweb-custom: update` тема и настройки не будут обновляться на каждом цикле. Тема применяется при **обновлении подписки** и при **переключении профиля**.

## 2. dropweb-theme — единый контракт темы (рекомендуемый)

```
dropweb-theme: <filter>,<accentHex>,<orb1Hex>,<orb2Hex>,<blur>[,<logoStyle>]
```

Все поля после `filter` позиционно опциональны — пропущенный или невалидный сегмент оставляет соответствующее поле без изменений.

### filter — алгоритм цветовой схемы
HSL-модификатор акцента и орбов (оттенок/hue сохраняется). Имя = как слать в заголовке; в скобках — название в интерфейсе приложения:

| filter | UI | Эффект |
|---|---|---|
| `fidelity` | Обычные | Точный акцент, без искажения. **Рекомендуемый / дефолт.** |
| `vibrant` | Яркие | Повышенная насыщенность |
| `monochrome` | Моно | Обесцвечивание (серый) |
| `neutral` | Нейтральные | Приглушённая насыщенность |
| `expressive` | Выразительные | Сдвиг оттенка |

### Остальные поля
| Поле | Назначение | Формат |
|---|---|---|
| `accentHex` | Акцент (кнопка, акценты) → primaryColor | 6 или 8 hex-цифр, `#` опционален |
| `orb1Hex` | Цвет верхних орбов фона → orbColorPrimary | hex |
| `orb2Hex` | Цвет нижнего орба фона → orbColorSecondary | hex |
| `blur` | Мягкость орбов: 1 = чёткие, 5 = диффузное свечение | число 1–5 (клампится) |
| `logoStyle` | Как показывать лого провайдера на карточке подписки (дашборд) | `watermark` \| `inline` |

### logoStyle — как показать лого на карточке подписки
Опциональное 6-е позиционное поле. Управляет ТОЛЬКО тем, как выводится лого провайдера (`dropweb-logo`) на карточке подписки на дашборде:

| Значение | Поведение |
|---|---|
| `watermark` | Текущий вотермарк: лого крупным пятном в углу карточки, перекрашенное в акцент и растворённое по краям. **По умолчанию.** |
| `inline` | Маленькое лого (32px, скруглённые углы) слева от имени сервиса в карточке. Лого рисуется как есть, без перекраски. |
| пустое / неизвестное | = `watermark` |

- Влияет **только** на карточку на дашборде; список профилей всегда использует `watermark`.
- Лого берётся из заголовка `dropweb-logo` и показывается **только** при включённом пользовательском тумблере лого (оба варианта). Если тумблер выключен или лого нет — в режиме `inline` строка показывает только имя сервиса (без запасного лого).

### Пример
```
dropweb-custom: update
dropweb-theme: fidelity,#15803D,#009938,#009938,2
```
Фирменный зелёный dropweb, точный фильтр, блюр 2, лого — вотермарк (поле опущено).

```
dropweb-custom: update
dropweb-theme: fidelity,#15803D,#009938,#009938,2,inline
```
То же самое, но лого показывается маленькой иконкой слева от имени сервиса.

> Если `orb1`/`orb2` пусты — орбы следуют за акцентом (Авто). Фильтр применяется и к акценту, и к орбам.

## 3. Пользовательский тумблер «Тема из подписки»

В приложении (**Настройки → Тема**) есть тумблер **«Тема из подписки»** (по умолчанию ВКЛ) — мастер-выключатель пользователя:

- **ВКЛ** — операторская тема (`dropweb-theme`) применяется
- **ВЫКЛ** — операторская тема игнорируется, пользователь оставляет свою

Оператор не может переопределить этот тумблер. **Для применения темы нужны оба условия:** `dropweb-custom: update` (оператор) И тумблер ВКЛ (пользователь).

## 4. dropweb-cabinet — действие личного кабинета

```
dropweb-cabinet: <HTTPS URL>
```

URL указывает на личный кабинет пользователя. Когда заголовок присутствует, приложение показывает действие «личный кабинет» и открывает указанный URL в браузере или custom tab.

**Требования:**

- значение должно быть полным HTTPS URL (например `https://cab.example.com`);
- если заголовка нет, приложение не показывает действие личного кабинета.

### Пример
```
dropweb-cabinet: https://cab.example.com
```

## 5. dropweb-logo — логотип провайдера на карточке

```
dropweb-logo: <URL картинки>
```

URL указывает на логотип провайдера (PNG/JPG/SVG; допускается base64-строка). Когда заголовок присутствует, приложение показывает **круглый логотип** в шапке карточки подписки (на месте бывшей иконки меню — само меню теперь открывается свайпом снизу-вверх по дашборду).

- Логотип обрезается в круг и обводится тонкой **акцентной обводкой**, которая загорается вместе с кнопкой подключения: яркий акцент при подключённом VPN, приглушённый — при отключённом.
- К логотипу применяется активный **фильтр темы** (`fidelity`/`vibrant`/`monochrome`/…), как к акценту и орбам — например при «Моно» логотип становится чёрно-белым.
- Если заголовка нет — логотип не показывается.

### Пользовательский тумблер «Лого из подписки»

В приложении (**Настройки → Тема**, над «Тема из подписки») есть тумблер **«Лого из подписки»** (по умолчанию ВКЛ). ВЫКЛ — логотип скрывается, даже если панель его отдаёт.

### Пример
```
dropweb-logo: https://example.com/logo.png
```

## 6. dropweb-renew-url / dropweb-topup-url — кнопки монетизации

Две ссылки, по которым на карточке подписки появляются **контекстные** кнопки. Логика показа — на стороне клиента; сами ссылки задаёт панель (могут быть персональными, с токеном пользователя). Кнопки показываются только когда это уместно — чтобы не быть постоянным баннером.

```
dropweb-renew-url: <HTTPS URL оплаты/продления>
dropweb-topup-url: <HTTPS URL докупки трафика>
```

| Заголовок | Кнопка | Когда показывается |
|---|---|---|
| `dropweb-renew-url` | «Продлить» | до конца подписки осталось меньше **3 дней** (в т.ч. если уже истекла) |
| `dropweb-topup-url` | «Докупить трафик» | остаётся меньше **10%** от лимита трафика |

- Условия показа считаются из стандартного `subscription-userinfo` (`expire`, `total`, `upload`+`download`). Без этих данных кнопки не появляются.
- `dropweb-renew-url` требует план с датой окончания (`expire > 0`), `dropweb-topup-url` — план с лимитом трафика (`total > 0`).
- Сработали **оба** триггера — кнопки в один ряд; один — кнопка на всю ширину.
- По нажатию открывается переданный URL (с подтверждением). Нет заголовка или условие не выполнено — кнопка не показывается.

### Пример
```
dropweb-renew-url: https://panel.example.com/pay
dropweb-topup-url: https://panel.example.com/buy-traffic
```

## 7. dropweb-update-url — запасной адрес файла обновлений

Запасной адрес `update.json` для встроенного обновления — **только Android-сборка вне Google Play** (sideload). Аппа использует его **только когда не ответило ни одно** встроенное и ни одно выученное зеркало манифеста — т.е. это последний шанс проверить обновление, когда все наши адреса заблокированы.

```
dropweb-update-url: <HTTPS URL файла update.json>
```

- **Не гейтится** `dropweb-custom` — заголовок читается всегда.
- Только `https`; иные схемы и мусор игнорируются. Адрес, совпадающий со встроенным зеркалом, тоже игнорируется (он и так проверяется).
- Безопасность: аппа ставит **только APK, подписанный ключом dropweb** (нативная проверка подписи). Чужой адрес не может подсунуть чужую сборку — в худшем случае покажет ложное «доступно обновление», которое не пройдёт проверку подписи.
- Манифест, полученный от провайдера, **никогда не добавляет зеркала** (поле `mirrors` из него игнорируется).

### Пример
```
dropweb-update-url: https://panel.example.com/dropweb/update.json
```

## 8. dropweb-account — вход по почте в приложении

Объявляет бэкенд аккаунта провайдера. Только с этим заголовком приложение (Android) показывает «Войти по почте»: пользователь получает код на почту, входит, и подписка импортируется сама. Без заголовка вход в приложении **не предлагается** — приложение-губка не знает ни одного бэкенда, пока его не объявит панель.

```
dropweb-account: <API base URL>[, <API base URL>...]
```

- Значение — один или несколько абсолютных базовых URL API (например `https://cab.example.com/api`), разделённых запятой, `;` или пробелами. Несколько адресов — **зеркала одного и того же бэкенда**: при сетевой ошибке приложение пробует следующий.
- Только `https`; `http` — только для loopback (`localhost`, `127.0.0.1`, `::1`). Невалидные элементы отбрасываются; если валидных не осталось — заголовка как будто нет.
- **Не гейтится** `dropweb-custom` — как и `dropweb-cabinet`, заголовок читается всегда.
- Вход идёт на бэкенд **текущего** профиля. Если профиль есть, но заголовка у него нет — вход недоступен (никаких запасных адресов, в том числе origin из `dropweb-cabinet`).
- **Магазинные сборки (Google Play, `PLAY_BUILD=true`) заголовок игнорируют**: там приложение — чистый клиент без аккаунта. Подписка в них добавляется ссылкой, QR или диплинком `dropweb://install-config?url=<ссылка подписки>`.

### Что должен реализовать бэкенд

API почтового входа кабинета (пути — относительно базового URL):

- `GET /cabinet/auth/email/challenge` (proof-of-work против спама), `POST /cabinet/auth/email/code/request`, `POST /cabinet/auth/email/code/verify` — запрос и проверка кода;
- `POST /cabinet/auth/refresh`, `POST /cabinet/auth/logout` — сессия;
- `GET /cabinet/subscription` — ссылка подписки для автоимпорта.

Необязательно (на `404` приложение мягко скрывает функцию или открывает кабинет без автовхода):

- `POST /cabinet/auth/app-handoff` — одноразовый токен для входа в кабинет без пароля (`/auto-login?token=…`).

### Привязка сессии

После входа приложение запоминает базы, на которых прошёл вход, и **все** дальнейшие запросы сессии (refresh, logout, подписка, handoff) шлёт только туда — даже если пользователь переключится на профиль другого провайдера или заголовок исчезнет. Управление аккаунтом (выход, удаление с устройства) остаётся доступным в меню, пока сессия жива.

### Автовход в кабинет

Handoff-токен бэкенда отдаётся **только** в кабинет профиля, чья подписка импортирована этим аккаунтом (`dropweb-cabinet` именно этого профиля). Кабинет любого другого профиля открывается обычной ссылкой, без токена: токен одного провайдера никогда не уходит кабинету другого.

### Пустое состояние собственной сборки

Пока в приложении нет ни одного профиля, заголовка взять неоткуда. Для этого случая издатель может зашить бэкенд по умолчанию при сборке:

```
DROPWEB_ACCOUNT_API=https://cab.example.com/api dart setup.dart android
# → --dart-define=DROPWEB_ACCOUNT_API=<base>[;<base>...]
```

Формат — как у заголовка. Значение используется **только** без профилей (и для сессий, созданных до привязки к бэкенду). В CI — переменная репозитория `DROPWEB_ACCOUNT_API`; не задана — бэкенда по умолчанию нет, вход появится только с заголовком.

### Пример
```
dropweb-account: https://cab.example.com/api, https://cab-mirror.example.net/api
```
